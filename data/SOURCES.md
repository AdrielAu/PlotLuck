## Offline search geography

- **Retrieved**: 2026-10-17 from ONS public ArcGIS services. Pinned releases: Built Up Areas December 2022 GB BGG, Local Authority Districts December 2025 UK BGC, Regions December 2025 England BGC. Exact query URLs, content hashes and byte counts are in [the source manifest](../docs/plans/nn2-geography-sources.json).
- **Permission**: ONS source item licence metadata links to [ONS geography licensing](https://www.ons.gov.uk/methodology/geography/licences). Digital boundaries are supplied under Open Government Licence v3.0. Attribution: Source: Office for National Statistics licensed under the Open Government Licence v.3.0. Contains OS data © Crown copyright and database right 2026.
- **Preparation**: `python -m plotluck.geography`; [reproduction, coordinate conversion and limitations](../docs/plans/nn2-geography-proof.md). Select E-prefixed GSS feature IDs; preserve each feature's authoritative name/ID/reference point/boundary linkage; precompute scoring district centroid memberships. Browser output contains no polygons or restaurant data.
- **Sample**: `geography-proof.json` contains four unmodified source features (Manchester BUA E63001295, Camden E09000007, City of London E09000001, London region E12000007) and only code/centroid fields for M1, NW5 and EC4V from the published scoring bundle. Its source features come directly from the pinned acquisition cache. Publisher spatial queries independently verified the expected memberships. Unlike restaurant samples, these public OGL boundaries may be redistributed; retain the attribution above.

One row per dataset, added in the same PR as the data (see [`AGENTS.md`](AGENTS.md)).

`python -m plotluck.sources` pulls each raw file to `data/full/raw/` on the server, writes `raw/<name>.provenance.json` (URL, edition, retrieval time, bytes, SHA-256, licence, attribution), extracts England to `<name>_england.csv` and cuts the sample. The runbook is [`docs/server.md`](../docs/server.md#6-where-datafull-comes-from); the code is `src/plotluck/sources.py`. Each sample folder keeps a copy of the provenance files in `data/sample/raw/`.

**Built files**: `python -m plotluck.build` (`src/plotluck/build.py`) writes the site bundle (`districts.csv`, `district_cuisine_supply.csv`, `vocabulary.json`, `model.json`, `reference_scores.json`) to `--out` (default: `bundle/` in the data folder; never the data folder itself), and always writes the private `restaurants.csv`, `label_policy.json` and `district_context.csv` (each district's source context, with its status as recorded, estimated or excluded, and the reasons) to the data folder, never to `--out`. Run results (`metrics.json`: NN1's district-grouped CV, baseline and loss per epoch) go to `--run` (default: `run/` in the data folder); `notebooks/train_nn1.ipynb` adds `loss_curves.png`. In `sample/` these are built from the sample files above, seed 0; rerun the command with `PLOTLUCK_DATA=sample` after changing the build.

**Sample box**: every row with coordinates inside latitude 51.49–51.51, longitude −0.12 to −0.08 (Southwark, the City and around; constant `SAMPLE_BBOX`). It has no randomness, so the files still join on district and location. All five sources were pulled and extracted on LinuxONE on 2026-10-17, and the sample was re-cut from those extracts with the same row counts. The provenance copies in `sample/raw/` are still from the laptop run (there is none for VOA); the server's are in `full/raw/`.

## Census demographics and tourism context

Archive schemas and MSOA member names were verified on 2026-10-17. Full-data acquisition and retraining on LinuxONE are still required. The committed new context files are synthetic, not observations; `plotluck.context.write_sample(data_dir(choice="sample"))` regenerates them from seed 101, as does `plotluck.sources sample`. Their provenance is `raw/context_sample.provenance.json`. Generated district/model/reference files in `data/sample/` and `web/models/` are rebuilt from those synthetic fixtures.

- **Census edition and URLs**: Census Day 2021-03-21, [TS007 single-year age](https://www.nomisweb.co.uk/output/census/2021/census2021-ts007.zip), [TS021 ethnic group](https://www.nomisweb.co.uk/output/census/2021/census2021-ts021.zip), [TS008 sex](https://www.nomisweb.co.uk/output/census/2021/census2021-ts008.zip). The extractor reads only `census2021-<table>-msoa.csv`. TS007 does not include OA or LSOA members. Counts use non-overlapping categories; age bands and totals are excluded from the mean. The 100+ category uses age 100.
- **Geography**: the raw ONSPD file must include `msoa21cd` (the August 2026 edition's 2021 MSOA column). Within each MSOA, counts are allocated according to the fraction of active English postcodes in each district, then summed before calculating means/shares. This is an estimate; it assumes equal residents per postcode within an MSOA, so commercial postcode concentrations can bias it. It is not the exact district population split. Cross-border demographics use English postcodes only. See [ADR 0005](../docs/adr/0005-district-demographics-and-tourism-context.md).
- **Extract schemas**: `district,average_age`; `district,ethnicity_asian_share,ethnicity_black_share,ethnicity_mixed_share,ethnicity_white_share,ethnicity_other_share`; `district,sex_female_share,sex_male_share`. Shares sum to one within each table. Missing values remain empty until training-fold median imputation. `run/metrics.json` counts the districts each table leaves empty, or has no row for, as `districts_without_census`. Sex here means the Census female/male measure, not gender identity.
- **Tourism**: a separate tiled Overpass query fetches nodes, ways and relations with exactly `tourism=hotel` or `tourism=attraction`, deduplicated by element type/ID. Museums, zoos, guest houses etc. without these tags are outside this definition. Ways/relations use their centre point. Extract: `osm_type,osm_id,tourism,lat,lon`. The build assigns each point to its nearest live English postcode; this approximates district membership and counts mapped elements, not visitors, rooms or unique physical venues across representations. A present but empty inventory means zero; a missing extract is an error.
- **Attribution**: Source: Office for National Statistics licensed under the Open Government Licence v.3.0. © OpenStreetMap contributors, [ODbL](https://www.openstreetmap.org/copyright). ONSPD attribution above also applies to the crosswalk. Public bundles contain district aggregates only.

## TripAdvisor European restaurants

- **Edition**: Kaggle `stefanoleone992/tripadvisor-european-restaurants`, version 1, updated 2021-05-18; scraped from tripadvisor.com in early May 2021. Raw: `raw/tripadvisor.zip` (one 680 MB CSV, 1,083,397 rows).
- **England filter**: `country == "England"`, giving 144,681 rows in the 2026-10-17 check run; the server pull will confirm it.
- **Sample**: 206 synthetic rows (200 plus six seeded cleaning defects; `SYNTHETIC_SEED = 43`) in the sample box, made up by `_synthetic_tripadvisor_rows` with the extract's columns and value formats. No real restaurant row is read. Rows cycle through the 13 sampled ONSPD districts using each district's first postcode point as an anchor; the coordinates are public postcode locations, not source restaurant locations. The seeded rows include specific, dish-style, umbrella, venue and set-aside cuisine tags, repeated chain names, missing ratings and traits, an out-of-range rating, missing category counts, a total below the category sum and a zero-review row. The last six rows seed the cleaning rules of issue #148: a second row with the link of row 20 and more reviews (exact duplicate), an upper-case copy of row 30's name about 22 m away with fewer reviews (near duplicate), a point in central Manchester (`far_from_postcode`, the only row outside the sample box), and three spellings of one chain name ("Synthetic Dough's", "Synthetic Doughs", "SYNTHETIC DOUGH’S") at three districts. Cleaning leaves 203 restaurants (200 labelled); the thresholds are constants in `build.py` (`FAR_FROM_POSTCODE_KM`, `NEAR_DUPLICATE_M`, `DROP_BRANCH_SUFFIX`), set from the full-data audit in `runs/2026-10-17-data-audit/`. The schema is unchanged and no real row is involved. Regenerate with `python -m plotluck.sources sample` on LinuxONE after the source extract is refreshed.
- **Kept columns**: `restaurant_link` (source ID), name, address, city, latitude, longitude, cuisines, `avg_rating`, `total_reviews_count`, `reviews_count_in_default_language`, the five category counts, `features`, `price_level`, `special_diets`, `vegetarian_friendly`, `vegan_options`, `gluten_free`. Values are copied unchanged: counts are strings like `347.0`, and `price_level` uses `€` symbols.
- **Licence**: see [ADR 0003](../docs/adr/0003-train-on-tripadvisor-derived-data-publish-only-model-outputs.md). The full file stays on LinuxONE; no laptop copies, no committed rows, and only model outputs are published.
- **Attribution**: TripAdvisor European restaurants, Stefano Leone (Kaggle).

## ONS Postcode Directory (ONSPD)

- **Edition**: August 2026. Raw: `raw/onspd.zip` (254 MB); the extract reads only `Data/ONSPD_AUG_2026_UK.csv`.
- **England filter**: country code `E92000001`, giving 2,279,344 postcodes, terminated ones included; 5,281 in the sample, across 13 districts.
- **Columns**: `pcds`, `district` (the outward code, `pcds` before the space), `lat`, `long`, `country_code`, `region_code`, `doterm` (blank while live), `imd25ind` (English IMD 2025 rank). ONSPD names columns by edition (`ctry26cd`); the extract finds them by pattern and writes fixed names.
- **Attribution** (required): Contains OS data © Crown copyright and database right 2026. Contains Royal Mail data © Royal Mail copyright and database right 2026. Source: Office for National Statistics licensed under the Open Government Licence v.3.0.
- **District circle radius**: `build.py` sets `radius_km` to the distance from the district centroid within which 90% of its postcode points lie, with a 0.3 km minimum, so the site can draw a circle that roughly covers each district without shipping boundaries. No new source is used: OS and ONS publish no open postcode-district boundaries ([Code-Point with Polygons](https://docs.os.uk/os-downloads/products/areas-and-zones-portfolio/code-point-with-polygons/code-point-with-polygons-overview) needs an OS licence). Limits: a circle over-covers long or crescent-shaped districts; points sit inside the real edge, so sparse rural districts may be slightly under-covered; districts with one or two postcodes (PO boxes, single buildings) get the minimum. The sample box clips districts, so sample radii are smaller than full-data ones.

## Census 2021 P004

- **Edition**: Census 2021, census day 2021-03-21, postcode-district geography as published by Nomis. Raw: `raw/p004.csv` (`pcdd_p004.csv`, England and Wales): 23,636 bytes, 2,302 districts, one `Count` each, summing to 59,597,557 residents (the England and Wales census total), so the small file is complete.
- **England filter**: districts with at least one English postcode in the ONSPD extract, giving 2,116 districts; 11 in the sample (EC3P and SE1P have no residents row). Cross-border districts stay, and their counts include Welsh residents.
- **Columns**: `district`, `residents`.
- **Attribution**: Source: Office for National Statistics licensed under the Open Government Licence v.3.0.

## OpenStreetMap restaurants

- **Edition**: live OSM through the public Overpass API, queried inside the `GB-ENG` area in the 34 one-degree tiles that hold an English postcode. A busy server's tiles are retried on the [maps.mail.ru mirror](https://maps.mail.ru/osm/tools/overpass/api/interpreter), and a failed pull resumes from the tiles it had finished; `endpoints` in the provenance lists every server that supplied a tile. `snapshot` and `snapshot_latest` are the oldest and newest tiles' `timestamp_osm_base`; a wide gap means a resumed pull or a lagging mirror. Raw: `raw/osm.json` (merged tiles).
- **Filter**: `amenity=restaurant` or `amenity=fast_food` (no other district-level OSM counts are agreed yet); nodes, ways and relations, with ways and relations at their centre point. The 2026-10-17 server pull gave 71,064 England rows, with snapshots from 2026-10-17T13:11:49Z to 13:57:51Z across both endpoints (it was resumed after the last tile failed); the sample keeps 452 of them.
- **Columns**: `osm_type`, `osm_id`, `amenity`, `cuisine` (blank when untagged), `name`, `lat`, `lon`.
- **Attribution** (required): © OpenStreetMap contributors, [ODbL](https://www.openstreetmap.org/copyright).

## VOA summary valuations

- **Edition**: 2026 compiled rating list, summary valuations, epoch 0004 baseline, published 2026-10-07. Rateable values are rents at the antecedent valuation date, 2024-04-01. Raw: `raw/voa.zip` (157 MB; one asterisk-delimited file of about 740 MB with no header). The layout is the VOA's *Compiled Rating List and Summary Valuation Data Specification*, linked from the download page. Summary valuations exist only for properties the VOA values by survey (shops, offices, warehouses and similar), which is why the list-entries file is not pulled: it has no floor areas.
- **Filter**: type `01` records with a blank To Date (current), SCAT code 234 (restaurants), 249 (shops), 409 (cafes) or 442 (takeaways), and a postcode found in the ONSPD England extract, giving 442,227 rows in the 2026-10-17 server pull. Of the 2,342 English districts in ONSPD (terminated postcodes included), 2,110 have an `NIA` valuation with a positive area and one more has only `GIA`, so 2,111 get a rent index and 231 stay blank.
- **Columns**: `uarn`, `postcode`, `district` (outward code), `scat_code`, `description`, `unit` (measuring standard: `NIA`, `GIA`, …, or `OTH` for a count of units), `total_area` (m², blank when absent), `adopted_rv` (£). Values are copied unchanged.
- **Index**: `build.py` sets `commercial_rent_index` to the district median of `adopted_rv / total_area` over valuations with a positive area. £/m² only compares within one measuring standard, so a district uses its `NIA` valuations, or its `GIA` ones when it has no `NIA`; other units are not used. A district with none stays blank and is not filled; `run/metrics.json` counts these as `districts_without_rent`. Rateable value is a rent proxy at the valuation date, not observed rent.
- **Sample**: 300 synthetic rows (`SYNTHETIC_SEED = 43`) spread over the sample districts by `_synthetic_voa_rows`; every 25th has no area. No real valuation is read.
- **Licence**: the download page says the files are "only available under our restricted licence" and that "An open government licence does not apply"; the [terms](https://www.tax.service.gov.uk/view-my-valuation/terms-and-conditions) restrict use to non-domestic rating purposes and prohibit onward disclosure. The team accepted this for non-commercial use, as for Tripadvisor under [ADR 0003](../docs/adr/0003-train-on-tripadvisor-derived-data-publish-only-model-outputs.md): the raw and extracted files stay on LinuxONE, and only the district index is published. This is a team decision, not a grant of rights.
- **Attribution**: Source: Valuation Office Agency. © Crown copyright and database rights 2026.
