# NN2 proposes a restaurant profile and search area

**Near-city amendment (#188), 2026-10-17:** `near` a named place without an explicit distance now uses that place's boundary. Remove the former automatic 5 km radius and radius question. Explicitly stated distances retain straight-line filtering and unit conversion. Ambiguous area choices and empty-scope guards remain unchanged.

**Place amendment (#183), 2026-10-17:** an omitted or unresolved place now requires an English city choice or a description at another resolution. This supersedes the original missing-location England default. Explicit England-wide requests remain valid. Compare a whole city when only a city is named, and accept borough boundaries when named. A shortened neighbourhood name such as Hammersmith proposes the labelled Hammersmith and Fulham borough for confirmation rather than silently adopting that larger extent. See the current NN2 plan.

**Superseded review-card amendment, 2026-10-17:** an intermediate direction had NN2 fill editable pickers and required confirmation before scoring. The later direct-results decision below supersedes that confirmation step.

**Earlier user amendment, 2026-10-17:** the product now accepts one free-text description and shows results immediately when its interpretation is clear and valid. Clarify only unclear or invalid details; remove the six-question flow, routine review card and results pickers. Editing the description explicitly re-runs interpretation. This supersedes the review-before-scoring requirement below; offline geography, strict validation, privacy and preservation of previous results remain in force. See the current contract in the NN2 plan.

**Current product contract:** one free-text description must account for area/range, cuisine, menu prices, rent, restaurant type and other requirements. Clear valid interpretations go directly to results; ask Erica's matching question only for missing, ambiguous or invalid fields, preserving independently valid values. An omitted or unresolved place requires an English city choice or a clearer area description; England-wide scope must be explicit. Explicit Unknown/Any/None answers are valid. Failed inference permits labelled manual completion. There is no routine review card or second confirmation step.

Agreed during the 2026-10-17 product interview. NN2 is required competition scope under ADR 0001. [Spec #110](https://github.com/AdrielAu/PlotLuck/issues/110) records the implementation contract; this decision records the settled product boundary.

A description such as "Thai restaurant in London" expresses both a restaurant profile and a search area. NN2 proposes one cuisine and supported traits, distinguishing explicit values, cue-based inferences and defaults. It also extracts location intent; a deterministic offline place catalogue supplies authoritative place identifiers and geometry. Ambiguous locations require a user choice. Without a resolved location, a city choice or a clearer area description is required before comparison. England-wide scope must be explicit.

The superseded review-card proposal had the user edit a whole draft and confirm with "Compare districts". The current flow instead asks targeted clarifications where needed; a new interpretation, failure or cancellation preserves previous results. Unsupported details are visible as unused in scoring.

NN1 retains its numeric input contract and scores whole postcode districts. Search areas filter which districts are compared, mapped and ranked. City/borough and bare-near membership use district centroids inside the confirmed boundary; explicitly stated distances use centroids within a confirmed straight-line radius. Overlapping districts whose centroids fall outside are excluded. These limits must be visible to users.

Browser inference and offline place resolution keep descriptions and interpretations in tab memory, with no server transmission or persistent query storage, and keep interpretation working after the VM expires. LinuxONE evaluation uses synthetic descriptions. This requires a downloadable browser model and local geography assets, whose size and feasibility remain to be measured. Device support, runtime candidates and acceptance gates are in [the integration plan](../plans/nn2-integration.md).
